Metodologia

O OpenFinancial transforma séries de preço, volume, notícias e relatórios oficiais em três probabilidades: alta, lateral e baixa. Esta página explica a conta, as fontes, os limites e o controle explícito de viés.

Em resumo: cada ativo recebe três probabilidades que somam 100%. A classe lateral é explícita e o modelo não escolhe uma direção quando os sinais são fracos. Nenhuma leitura é recomendação de investimento.

1. O que é o OpenFinancial

O OpenFinancial é um panorama estático e aberto dos ativos acompanhados da B3. Ele combina duas camadas: dados de mercado (preço, volume, índices e indicadores) e análises probabilísticas (probabilidades por período, cenários, projeções e leitura textual).

A interface não exige cadastro, não usa cookies de rastreamento e não envia dados pessoais para a API. Toda a renderização dos gráficos acontece no navegador, em SVG, sem bibliotecas externas.

O produto é informativo. Ele ajuda a organizar cenários e a comparar ativos; não decide por você e não substitui a leitura dos documentos oficiais das companhias.

A ordem de tentativa é API → CDN → demo para análises e CDN → demo para ativos e séries. Os selos no topo do panorama mostram qual fonte respondeu em cada camada. Quando o selo diz demo local, os números são sintéticos e servem apenas para validar a interface.

A CDN entrega JSON estático e cacheável; a API entrega o panorama já calculado por período. Separar as duas camadas permite atualizar preço com frequência e recalcular análises em outro ritmo, sem acoplar o site ao servidor de análise.

3. Como a probabilidade é calculada

O modelo parte de um score técnico S entre −1 e +1, combinando seis famílias de sinal. Cada família é normalizada com tanh para evitar que um único indicador domine a leitura.

SinalPesoLeitura
Momentum de 21 sessões ajustado por volatilidade0,36direção recente
MM20 versus MM500,24tendência curta contra média
RSI 140,18excesso de compra ou venda
MACD0,12aceleração da tendência
Volume versus média de 20 sessões0,10participação do movimento
Preço versus MM2000,08tendência longa

Os pesos somam 1,08 de propósito. Quando todos os sinais apontam para o mesmo lado, o score satura no limite de ±1. Esse corte impede que a softmax produza 0% ou 100% e mantém a leitura dentro de uma faixa de incerteza.

O score vira probabilidade por uma softmax de três classes, com uma âncora neutra explícita: 

Z = e^(2,2·S) + e^(−2,2·S) + 1,4
p_alta    = e^(2,2·S) / Z
p_baixa   = e^(−2,2·S) / Z
p_lateral = 1,4 / Z

A âncora 1,4 faz a classe lateral valer cerca de 41% quando o score é zero, contra 29,4% para alta e 29,4% para baixa. Para que alta ou baixa alcancem 70%, o score precisa ser forte. Essa escolha é deliberada: o modelo começa neutro e só se inclina quando os dados se inclinam.

A confiança exibida ao lado da leitura combina a magnitude do score com o tamanho da amostra: 

confiança = min(0,92; 0,48 + 0,34·|S| + 0,10·min(1; n/252))

Ela não é a probabilidade de acerto. É uma medida de quanto o modelo confia na própria leitura, e cai quando o histórico é curto ou os sinais são ambíguos.

4. Controle de viés

Análises econômicas costumam pender para o pessimismo: notícias negativas recebem mais espaço, cenários de queda parecem mais “prudentes” e a incerteza é tratada como risco de baixa. O OpenFinancial controla esse viés em cinco pontos.

  1. Classe neutra explícita. O modelo tem três saídas. Não existe a obrigação de escolher entre alta e baixa; a lateralidade é uma resposta legítima.
  2. Âncora neutra na softmax. A probabilidade lateral não é um resíduo: ela tem peso próprio e domina quando o score é fraco.
  3. Simetria entre alta e baixa. Os pesos de e^(2,2·S) e e^(−2,2·S) são iguais em módulo. Não há penalidade assimétrica para o otimismo.
  4. Notícia não é sentença. No texto gerado por LLM, cada evento entra com fonte, data e impacto declarado (positivo, negativo ou neutro). O prompt proíbe linguagem de certeza e exige que o cenário lateral seja mencionado quando relevante.
  5. Leitura humana no fim. A página mostra probabilidades, confiança, indicadores e fontes lado a lado. O objetivo é dar contexto para uma decisão humana, não substituí-la.
Atenção: controle de viés não significa otimismo. Se os dados apontarem queda, o modelo dirá queda — com probabilidade, fonte e incerteza. O compromisso é com a simetria, não com um resultado agradável.

5. Períodos e projeções

O panorama é recalculado para cinco janelas: 1 mês (21 sessões), 3 meses (63), 6 meses (126), 1 ano (252) e 5 anos (1.260). O seletor de período no topo troca a janela de todas as análises, da série de probabilidades e da tabela.

A projeção à frente usa um movimento geométrico browniano calibrado pela volatilidade recente. São desenhados os quantis 10, 25, 50, 75 e 90% para 21, 42 ou 63 pregões, conforme o período. A linha central é o cenário mediano; as bandas mostram a dispersão. Projeção não é previsão: é uma faixa de incerteza condicionada ao passado recente.

Os cenários de alta e baixa usam retornos simétricos de ±1 desvio-padrão do horizonte, calculados pela volatilidade diária recente e pela raiz do número de pregões. O cenário lateral fica em 0%. Suporte e resistência continuam exibidos como níveis de referência, mas não definem os retornos dos cenários — assim a baixa não zera quando o preço está no mínimo da janela.

6. Notícias e relatórios oficiais

O panorama lista eventos do período com fonte e impacto declarado. As fontes previstas são B3, CVM, BCB, IBGE e comunicados das companhias. O texto narrativo é produzido por modelos OpenCode no servidor, nunca no navegador.

O token do provedor de LLM fica em variável de ambiente do serviço. O navegador recebe apenas o texto final e a lista de fontes. Se o provedor estiver indisponível, a API devolve uma leitura determinística gerada pelo motor de probabilidades — o site continua funcionando, sem inventar notícias.

O prompt do narrador exige quatro regras: (1) citar as fontes recebidas; (2) não afirmar certeza; (3) manter os três cenários visíveis; (4) encerrar com o aviso de que o conteúdo não é recomendação de investimento.

8. Limites do modelo

  • Não é causal. O modelo descreve regularidades estatísticas; não explica por que o preço se move.
  • Não lê fundamentos. Balanços, governança e notícias entram como contexto, não como valuation.
  • Latência. A CDN pode estar alguns minutos atrás do mercado; a API informa o horário de geração.
  • Eventos corporativos. Desdobramentos, dividendos e mudanças de índice exigem ajuste na série.
  • Liquidez. Ativos com baixo volume distorcem sinais de volume e volatilidade.
  • Dados demo. Quando o selo indica demo local, todos os números são sintéticos.
  • Sem personalização. O modelo não conhece seu horizonte, seu risco ou seus objetivos.
Não é recomendação. O OpenFinancial não indica compra, venda ou manutenção de ativos. Decisões de investimento são de responsabilidade do usuário e devem considerar seus objetivos, sua tolerância a risco e, quando necessário, um profissional habilitado.

9. Atualização e reprodutibilidade

Os dados de demonstração são gerados por tools/gerar_dados_demo.py, com semente fixa 20261113 e data-base 2026-11-13. A mesma semente produz a mesma série, o que permite testar a interface e o contrato da API sem depender de rede.

Em produção, o fluxo previsto é: ingestão das séries oficiais → cálculo do motor de probabilidades → publicação dos JSON na CDN e na API → leitura pelo site. Cada payload carrega fonte, atualizadoEm e demo para que a origem seja sempre auditável.

O site é estático e não tem etapa de build. A pasta publicada no GitHub Pages contém HTML, CSS, JavaScript e os JSON de fallback.
